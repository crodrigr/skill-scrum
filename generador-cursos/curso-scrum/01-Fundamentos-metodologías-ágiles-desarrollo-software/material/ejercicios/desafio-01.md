# 🔴 Desafío 01 — Elegir y justificar un enfoque

> 🔴 **Nivel:** Desafío · 🎓 **Resultados de aprendizaje:** RA-1, RA-2, RA-3, RA-4, RA-5, RA-6

## 🧱 Estado inicial

Tenés dos casos.

- **Caso A — Aplicación de turnos para gimnasios.** Una empresa nueva quiere lanzar su
  aplicación cuanto antes. No sabe qué funciones usarán los clientes y espera cambiar las
  prioridades cada mes. Puede reunirse con el equipo varias veces por semana. No hay normas
  que regulen el proyecto.
- **Caso B — Software de un equipo de laboratorio.** Una norma exige documentar cada requisito
  y cada prueba antes de usar el sistema. El contrato fija alcance, precio y plazo. Los
  requisitos están completos y firmados, y casi no cambiarán.

## 🛠️ Proceso esperado

1. Para cada caso, completar una **tabla de criterios** (requisitos, cliente, contrato y
   regulación, riesgo, entregas).
2. Elegir un **enfoque** (tradicional o ágil) y **una metodología concreta** de la clase para
   cada caso.
3. Justificar cada elección con **al menos dos ventajas y dos desventajas** del enfoque
   elegido.
4. Señalar **un riesgo** de cada elección y cómo lo mitigarías.
5. Escribir una frase que explique por qué no se eligió el otro enfoque en cada caso.

## ✅ Resultado esperado

- ☑️ Dos tablas de criterios completas y coherentes con la descripción de cada caso.
- ☑️ Un enfoque y una metodología por caso, con justificación.
- ☑️ Ventajas, desventajas, riesgo y mitigación por caso.
- ☑️ Una explicación de por qué el otro enfoque no encaja.

## 🚧 Restricciones

- 🚫 No elegir el mismo enfoque para los dos casos.
- 🚫 No decir que un enfoque es "mejor" sin ligarlo a las características del caso.
- 🚫 Elegir solo entre los enfoques vistos en la clase.

## 🎓 Resultados de aprendizaje

- RA-1: Explicar qué es una metodología de desarrollo de software y qué es una metodología ágil.
- RA-2: Enunciar el manifiesto ágil, sus valores y sus principios.
- RA-3: Identificar las ventajas y desventajas de las metodologías ágiles.
- RA-4: Describir las metodologías tradicionales Cascada, Prototipado y Espiral.
- RA-5: Describir las metodologías ágiles Kanban, Lean y Programación Extrema (XP).
- RA-6: Comparar metodologías tradicionales y ágiles y justificar cuál conviene.

## 🧪 Casos de prueba

| Verificación | Resultado esperado |
|---|---|
| Enfoque del Caso A | Ágil |
| Enfoque del Caso B | Tradicional (Cascada o Espiral) |
| Criterios usados en el Caso A | Requisitos cambiantes, cliente disponible, necesidad de valor temprano |
| Criterios usados en el Caso B | Requisitos cerrados, norma que exige documentación, contrato de alcance fijo |
| Ventajas y desventajas | Al menos dos de cada una por caso, coherentes con el enfoque elegido |
| Riesgo y mitigación | Un riesgo por caso, con una mitigación posible |
| Justificación del descarte | Se explica por qué el otro enfoque no encaja con las características del caso |
