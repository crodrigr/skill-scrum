# 🟢 Básico 02 — Épica, historia o tarea

> 🟢 **Nivel:** Básico · 🎓 **Resultados de aprendizaje:** RA-2, RA-3

## 🧱 Estado inicial

Un equipo desarrolla una **aplicación de recetas de cocina**. Tenés ocho elementos del trabajo y una
descripción general del producto.

**Descripción del producto.** La aplicación quiere que cualquier persona pueda decidir qué cocinar
y encontrar la receta en poco tiempo.

**Elementos**

- **1.** Gestionar mis recetas favoritas.
- **2.** Como usuario quiero buscar recetas por ingrediente para cocinar con lo que tengo.
- **3.** Diseñar la pantalla de resultados de la búsqueda.
- **4.** Planificar el menú de la semana.
- **5.** Como usuario quiero guardar una receta como favorita para encontrarla después.
- **6.** Probar el guardado de una receta sin conexión.
- **7.** Como usuario quiero ver la lista de compras de una receta para saber qué comprar.
- **8.** Compartir recetas con otras personas.

## 🛠️ Proceso esperado

1. Clasificar cada elemento (1 a 8) como **épica**, **historia de usuario** o **tarea**.
2. Justificar la clasificación de los elementos 2, 3 y 4 con una frase cada uno.
3. Formular el **objetivo del producto** a partir de la descripción.

## ✅ Resultado esperado

- ☑️ Ocho clasificaciones, una por elemento.
- ☑️ Tres justificaciones que distingan valor para quien usa el producto, paso del equipo y bloque
  grande de trabajo.
- ☑️ Un objetivo del producto que exprese el valor buscado y se pueda comprobar.

## 🚧 Restricciones

- 🚫 Cada elemento recibe una sola clasificación.
- 🚫 El objetivo del producto no puede ser una lista de funciones.
- 🚫 Cada justificación debe tener una sola frase.

## 🎓 Resultados de aprendizaje

- RA-2: Construir un Product Backlog: definir el objetivo del producto y organizar el trabajo en épicas.
- RA-3: Redactar historias de usuario con su criterio de aceptación y su prioridad, a partir de una épica.
